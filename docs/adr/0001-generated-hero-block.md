# ADR-0001：README 头部结论纳入 marker 渲染

- **状态**：已采纳（2026-11-10）
- **影响面**：`scripts/build.py`、`README.md`、`tests/test_readme_hero.py`

## 背景

README 里有两类内容：由 `build.py` 用 marker 替换的生成块（`SNAPSHOT_*` / `TOP15_*` / `PLANS_GUIDE` / `FRONTIER`），以及正文里手写的叙述。三张榜单的「当前第一名是谁、多少分、最低等效价多少、池里有几个模型」写在开头三个 bullet 里，属于手写。

2026-11 维护时实测，这四项**全部过期**：

| 手写 | 实际 |
|---|---|
| 通用榜第一 `claude-fable-5.1`，70.5 分 | `claude-opus-5.5`，77.7 分 |
| 文本榜第一 `gpt-6-astra`，77.7 分 | `claude-opus-5.5`，82.3 分 |
| 订阅折算最低约 `$0.005/M` | `$0.001/M`（gpt-6-luna） |
| 精选 50 个模型 | 73 个 |

同段的手写前沿序列也已换了两代（写着 gpt-5.4-nano → claude-fable-5.1 共 9 个点，实际只剩 5 个点，终点是 claude-opus-5.5）。

根因不是笔误：手写结论和自动榜单不同源，只要新增模型，就必然漂移一次，而且没有任何机制会报警。

## 决策

把「会随数据变化的结论」全部交给渲染，正文只保留不随数据变化的定性描述：

1. 新增 `HERO` marker，`build.hero_block()` 从 `results/*_scored.csv` + `model_registry.json` 渲染三个 bullet（含池规模）。
2. `FRONTIER` 块从「只有一张图」扩为「一句前沿序列描述 + 图」，序列来自 `plot_frontier.render()` 的返回值。
3. `tests/test_readme_hero.py` 断言 README 的 HERO / FRONTIER 首行与当前渲染结果逐字一致——离线构建不刷新 README（`stale` 分支），所以测试是这条不变量的实际守门人。
4. 正文里凡是提到池规模的地方不再写死数字（改为「见顶部」），消除第二处漂移源。

## 后果

- 头部数字永远与榜单同源，新增模型不再需要人手改 README。
- 代价：`HERO` 区块**不能手改**（改了测试就红），文案调整必须改 `_HERO_COPY`。
- 仍需人工维护的部分：权重说明段（`通用榜 Top 15` 下方那句）。它是纯文本、结构长，暂不渲染；但权重结构本身有 `config.json` 兜底，且 2026-11 维护时已逐项核对过。

## 替代方案

- **只改数字**：最小改动，但下个月仍会漂移，已否。
- **加 doc-code 一致性测试但不渲染**：能报警却不能自愈，仍需人工同步，故只作为补充而非主方案。
